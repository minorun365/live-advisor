# 動作の詳細

## 動き方

| 段 | 何をするか | 使うもの |
|---|---|---|
| 見張り | 確定した発言を読み、持ち帰り、議論の詰まり、相手の質問を示す語を拾う | モデルなし |
| 判定 | 拾うべきことを選んでカードにする | Haiku |
| 調査 | 一般化した問いを公式情報で確かめる | Opus＋Web 検索 |
| 提案 | 議論の要点と調査結果から、進め方を1つ推奨する | Opus（道具なし） |
| 経緯 | 設定した記録フォルダから、同じ相手・同じ案件の過去の記録を探して要約する | Sonnet＋読み取りだけの道具（Read・Grep・Glob） |

調査の段は書き直した問いだけを受け取り、会議の発言を読みません。発言を読む判定と提案の段は Web 検索を使いません。経緯の段は会議の発言を読みますが、使えるのは記録フォルダを読む道具だけで、Web 検索もファイルの書き込みもできません。

## 経緯

設定の `contextFolders` に記録フォルダを書いたときだけ動きます。

最初は、会議の窓のタイトル（予定の件名のことが多い）が分かった時点か、発言が150字たまった時点で探します。見つからなければ最初の判定の直後にもう1回、それでも無ければ5分後に最後の1回を探します。社名や話題が会議の冒頭で出るまでは当たらないためです。

経緯が見つかったあとも、「前回」「でしたっけ」「見積」「宿題」のように、前に決めたことや出した金額を問う発言が出たら、その発言に答える記録をその場で探し直します。見つかればその問いを題にした経緯のカードを足し、要約を提案の材料に加えます。探し直しは1会議4回まで、前回から2分以上空けます。

見つかると「経緯」のカードを1枚出します。前回までの到達点、決まったことや残っている宿題、今日聞くとよいこと、根拠にした記録のファイルが並びます。ファイル名を押すと開きます。見つからなければカードは出ません。

経緯の要約は、そのあとの論点の提案と「今すぐ提案」の提案にも渡します。自動で動く回数の上限には数えません。

## 判定の頻度

次のときに判定します。前回の判定から増えた文字が40字未満なら、どの場合も動きません。

- 前回（初回は録音の開始）から1分たったとき
- きっかけの語が出たとき（前回から30秒以上あいている場合）
- パネルを開いたとき（前回から30秒以上あいている場合）

会議中に調べたくなるのは、話題が出てから1分以内のことが多いためです。判定は Haiku なので、回数が増えても費用は小さく収まります。

## 今すぐ提案（直近の話を調べる）

パネルの「今すぐ提案」か、どのアプリを使っていても `⌃⌥R` を押すと、直近2分の発言から調べたいことを選んで Web で調べます。直近2分の発言が80字に満たないときは、最後の発言から1500字ぶんさかのぼって読みます。

調べ方は2段です。Haiku が道具なしで直近の発言を読み、会社名や人名を外した問いを1〜2本書きます。Web 検索へ渡るのはこの問いだけで、2本なら同時に調べます。2本目の答えは補足の先頭に入ります。

公開情報で答えが出るものが直近に無ければ、それまでの文字起こし（直近8000字まで）から今やるとよいことを1つ提案します。この提案は Opus を道具なしで呼びます。どちらも自動で動く回数の上限には数えず、動いている間はもう一度押せません。

## 依頼を確認（Claude アプリへ渡す）

パネルの「依頼を確認」を押すと、直近5分の発言から、本人がやると言った作業と、相手から頼まれて本人が引き受けた作業を最大3件拾い、1件ずつカードにします。直近5分に発言が無いときは、最後の20行を読みます。拾うのは登録・起票・下書き・資料づくり・調べもののように、パソコンの上で済む作業だけです。

読むのは Sonnet で、道具も設定も渡しません。助言さん自身は何も実行しません。

カードには作業の題と、根拠になった発言をそのまま載せます。「Claude に渡す」を押すと、Claude デスクトップアプリに新しいセッションが開き、入力欄に依頼文・根拠の発言・会議の窓のタイトル・会議フォルダの場所が入ります。送信はしないので、読んで Enter を押すことが実行の合図になります。実行と、そのあとのやり取りはデスクトップアプリの中で進み、そちらの MCP・許可の確認・会話の履歴がそのまま使えます。

開くのは `claude://code/new?q=…` のリンクです。デスクトップアプリを複数のアカウントで同時に起動していると、先に起動したほうへ届きます。

## 文の長さ

質問は「？」で終わる18字以内、答えは25字以内、補足は25字以内の箇条書き3行までです。モデルの出力をアプリが数え、超えた行だけ Haiku で1回書き直します。書き直しが失敗したら元の文を出します。

## カードの並び

カードは1列で、最後に変わったものが一番上に来ます。

相手の質問と論点は、答えや推奨が付いてから並べます。問いだけのカードは、いま聞いていた話の言い直しで、読んでも新しいことが無いためです。持ち帰りと食い違いは、それだけで意味があるので答えが無くても並べます（確信度0.6未満は並べません）。押して調べている間のカードだけは、調べていることが分かるように並べます。

未読のカードは種別の左に黒い点が付きます。パネルに1.5秒ほど映ると、閉じなくても既読になります。カードを押したときも既読です。答えが後から出たカードはもう一度未読になります。

カードを押すと理由や出典が開きます。調べて答えが出る持ち帰りの候補を押すと、開くと同時に調査が始まります。閉じる操作はなく、古いカードは下へ流れていきます。

## 押さなくても動くカード

| カード | 自動で動く条件 | 1会議の上限 |
|---|---|---|
| 相手の質問・持ち帰り・食い違い | 公開情報を調べて答えが出るもの。確信度や話者は問わない | 15件 |
| 論点 | 確信度0.85以上。直近10分に同じ種類の提案があれば候補に回す | 5回 |

判定は、誰も質問していなくても、話に出た製品名・サービス名・制度・規格や、料金・上限・期限のような数字の主張を「相手の質問」として拾い、先に調べておきます。会議中に本人が「調べなきゃ」と思うのは、問いとして口に出る前のことが多いためです。調査は1件ずつ順に進めます。

話者が分からない文字起こしでは、「本人の持ち帰り」「相手の質問」の判定が働きにくくなります。文字起こしちゃんの日本語モードでヘッドホンを使うと話者が分かれます。

## 失敗したとき

Claude の呼び出しが失敗すると、パネルの上に理由を1行出し、次の判定で自動的にやり直します。理由は Claude Code が返す JSON の `subtype`・`api_error_status`・`result` から決めます。出力全体を文字列で探すと、成功時にも入っている `"budget":0` のような数え欄に反応して取り違えるためです。

| 表示 | 条件 |
|---|---|
| 上限額に達したので打ち切りました | `subtype` が `error_max_budget_usd`（1回の呼び出しに付けた上限額を超えた） |
| Claude の利用上限に達した可能性があります | 429、または利用上限の文面 |
| Claude に一時的につながりません | 5xx・混雑・通信の失敗。5秒後に1回だけその場でやり直す |
| Claude Code にログインしてください | 401、または未ログインの文面 |

ログには数字と、`api_error_status`・`terminal_reason` のコードだけを残します。エラーの文面はプロンプトを引用しうるので残しません。

## パネルを開いた回数

録音が終わると、ログにその会議でパネルを開いた回数と、そのうち前回開いたときから新しいカードが無かった回数（`empty_opens`）を数字だけで残します。直したあとに空振りが減ったかを測るためです。

## 止め方

パネルの「この会議では止める」を押すと、その会議の判定を止めます。「再開する」で戻せます。次の録音では再び自動で動きます。

## スクリーンショット

パネルはふつうのウィンドウと同じようにスクリーンショットに撮れます。macOS では両方が同じ設定で決まるので、画面共有にも映ります。共有中に相手へ見せたくないときは、メニューバーのアイコンで閉じます。

パネルの外を押すと閉じます。ただしスクリーンショットを撮っている最中のクリックでは閉じません（macOS の撮影画面が動いている間は外のクリックを無視します）。

## 保存されるファイル

会議フォルダ（`~/Library/Application Support/LiveTranslator/Sessions/<日時>/`）へ次のファイルを書きます。

| ファイル | 中身 |
|---|---|
| `advisor-cards.json` | カードの内容 |
| `advisor.md` | 読むための記録。AI の提案であり決定事項ではないと冒頭に書く |
| `advisor-queries.jsonl` | Web 検索へ送った問い |
| `advisor-context.jsonl` | 経緯の段が根拠にした記録のファイルのパス |

処理の時間、トークン数、費用は `~/Library/Logs/LiveAdvisor/live-advisor.log` に残ります。会議の本文は書きません。

## 設定

設定ファイルは任意です。ログイン時に起動したアプリには環境変数が渡らないので、ファイルで指定します。

```text
~/Library/Application Support/LiveAdvisor/config.json
```

```json
{
  "claudeCommand": "~/bin/my-claude"
}
```

`claudeCommand` は呼び出すコマンドです。既定は `claude` で、`~/.local/bin`、`~/.claude/local`、`~/.npm-global/bin`、`/opt/homebrew/bin`、`/usr/local/bin`、`/usr/bin`、`/bin` の順に探します。これ以外の場所に入れているときは絶対パスを書いてください。変更後はアプリを起動し直します。

`contextFolders` は経緯の段が読む記録フォルダの一覧です。案件ごとの議事録やメモを置いているフォルダを書きます。既定は空で、そのときは経緯の段は動きません。存在しないフォルダは無視します。

```json
{
  "contextFolders": ["~/notes/clients", "~/notes/meetings"]
}
```

記録フォルダの中身は、会議の発言と同じく Claude Code のログイン先へ送られます。送ってよいものだけを置いたフォルダを指定してください。

## 開発

```bash
scripts/test.sh
scripts/snapshot.sh /tmp/panel.png
scripts/e2e.sh /tmp/live-advisor-e2e
```

`e2e.sh` は架空の会議を流し、Claude Code を実際に呼んで最後まで通します。ログイン中の Claude の利用枠を少し使います。

## 文字起こしちゃんが無いとき

パネルを開くたびにアプリの ID で文字起こしちゃんを探します。見つからなければ、パネルの先頭に案内と導入ページへのボタンを出します。入れたあとは、次にパネルを開いたときに消えます。
